# AI Bug Fixer 安全機制

## 目前的安全措施

### 1. URL 驗證（已實作）

**檢查項目：**
- ✅ 只允許 http/https 協議
- ✅ 封鎖色情、賭博相關 TLD（.xxx, .adult, .porn, .sex）
- ✅ 封鎖可疑關鍵字（porn, xxx, adult, sex, casino, gambling）
- ✅ **只自動批准學術網域**：
  - .edu.tw
  - .edu
  - .gov.tw
  - .ac.*
  - 常見大學網域（ntu.edu, ncku.edu, nthu.edu, nctu.edu, nycu.edu）

**行為：**
- 學術網域 → 自動更新 ✅
- 非學術網域 → 拒絕並轉交人工審核 ⚠️

### 2. Alias 新增（相對安全）

**為什麼較安全：**
- 只新增關鍵字，不修改現有資料
- 最壞情況：新增無用的 alias
- 不會導致用戶看到惡意內容

**限制：**
- 必須找到對應的學校和系所
- 不能憑空建立資料

## 攻擊場景與防禦

### 場景 1：惡意 URL 替換
**攻擊：** `/bug 台大國企所網址是 https://evil-site.com`

**防禦：**
```
isValidAndSafeUrl('https://evil-site.com') → false
回應：「網址格式不正確或不是學術網域，已轉交人工審核」
不會更新資料庫 ✅
```

### 場景 2：色情網站
**攻擊：** `/bug 台大資工網址是 https://xxx-university.com`

**防禦：**
```
檢測到 'xxx' 關鍵字 → false
回應：「網址格式不正確或不是學術網域，已轉交人工審核」
不會更新資料庫 ✅
```

### 場景 3：釣魚網站（學術網域偽裝）
**攻擊：** `/bug 台大資工網址是 https://ntu-edu-tw-fake.com`

**防禦：**
```
不符合 .edu.tw 結尾 → false
回應：「網址格式不正確或不是學術網域，已轉交人工審核」
不會更新資料庫 ✅
```

### 場景 4：合法學術網域
**正常使用：** `/bug 台大資工網址是 https://www.csie.ntu.edu.tw`

**處理：**
```
符合 ntu.edu 模式 → true
自動更新資料庫 ✅
回應：「已成功更新系所官網網址」
```

## 未來改進建議

### 短期（1-2 週）
1. **建立審核表** `url_update_requests`
   - 儲存所有 URL 更新請求
   - 非學術網域進入待審核狀態
   - 管理員可在後台批准/拒絕

2. **記錄用戶 ID**
   - 追蹤誰提交了修改
   - 可以封鎖惡意用戶

3. **Rate Limiting**
   - 每個用戶每天最多 5 次 bug 回報
   - 防止大量惡意提交

### 中期（1 個月）
1. **URL 活性檢查**
   - 自動訪問 URL 確認可達
   - 檢查 HTTP status code
   - 確認是否真的是大學網站

2. **AI 內容檢查**
   - 用 Gemini 檢查網頁內容
   - 確認是否為學術內容

3. **管理後台**
   - 查看所有待審核請求
   - 批量處理
   - 查看用戶提交歷史

### 長期（3 個月+）
1. **信譽系統**
   - 追蹤用戶提交的準確率
   - 高信譽用戶可以更快通過審核
   - 低信譽用戶自動進入人工審核

2. **社群驗證**
   - 多個用戶回報同一個問題才自動修復
   - 類似 Wikipedia 的編輯機制

## 當前風險評估

| 風險類型 | 嚴重性 | 可能性 | 防禦狀態 |
|---------|--------|--------|---------|
| 色情網站 | 高 | 低 | ✅ 已防禦 |
| 釣魚網站 | 高 | 中 | ✅ 已防禦 |
| 惡意 Alias | 低 | 中 | ⚠️ 部分防禦 |
| 大量垃圾提交 | 中 | 中 | ❌ 未防禦 |
| 合法但錯誤的 URL | 低 | 高 | ⚠️ 需人工審核 |

**總結：** 目前對高風險攻擊（色情、釣魚）有基本防禦，但缺乏 rate limiting 和審核機制。
